# Правки дашборда «Аналитика маркетплейса»

`apply_review_fixes.py` применяет к Superset правки P0/P1/P2 из ревью
дашборда: переводит датасеты на витрины ClickHouse, правит form_data
чартов, раскладку и метаданные дашборда через REST API.

SQL витрин в этом скрипте нет — он живёт в `clickhouse_marts.sql`
(база `marketplace_marts`) и применяется загрузчиком, см. «Семантический
слой» в корневом README. Скрипт только переключает датасеты Superset на
готовые витрины: `sql=None`, схема `marketplace_marts`. Датасет при этом
не пересоздаётся и не переименовывается, поэтому чарты, ссылающиеся на
него по id, продолжают работать.

**Порядок важен:** витрины должны быть в ClickHouse раньше, чем скрипт
переведёт на них датасеты. Достаточно одного прогона
`load_to_clickhouse.py` — он применяет их при любой загрузке, включая
no-op на уже загруженный день.

Скрипт идемпотентен — повторный запуск приводит инстанс в то же
состояние, а не накапливает изменения. По умолчанию он ничего не пишет,
а печатает план.

## Запуск

```bash
pip install -r requirements-superset.txt

python superset/apply_review_fixes.py --url http://superset.example.com:8088 \
    --username admin --phases p0,p1,p2
```

Зависимость одна — `requests`; она вынесена отдельным файлом и
намеренно не тянет `requirements.txt`: скрипт ходит по HTTP и не
трогает данные, pandas и pyspark ему не нужны. Для воспроизводимой
установки есть `requirements-superset.lock` с хешами.

### Запуск без участия человека

Чтобы скрипт мог работать сам — из планировщика или из чужой сессии —
положи креды в файл, который он прочитает:

```bash
mkdir -p ~/.superset && cat > ~/.superset/credentials.json <<'JSON'
{"url": "http://localhost:8088", "username": "superset_admin", "password": "..."}
JSON
chmod 600 ~/.superset/credentials.json
```

Скрипт откажется читать файл, доступный кому-то кроме владельца: файл с
паролем, который виден всем, — это не защита, а её видимость.

Порядок источников: аргумент командной строки, потом переменная
окружения, потом файл. Пароль не передаётся ни аргументом (виден в
списке процессов), ни без нужды окружением.

### Удаление чартов

```bash
python superset/apply_review_fixes.py --delete-charts 44,45,46 --apply
```

Только по явному списку id и только тех, на которые не ссылается
раскладка дашборда, — опечатка в списке не снесёт рабочий чарт. Без
`--apply` печатается список к удалению.

Пароль скрипт спросит скрытым вводом. Передавать его в командной строке
не нужно: оттуда он попадает в историю оболочки и в список процессов.
Для CI, где спрашивать некого, остались `SUPERSET_PASSWORD` и
`--password`; если пароля нет, а ввод или вывод перенаправлены, скрипт
скажет об этом и выйдет, а не повиснет на приглашении.

Показанное выше — только план. Чтобы записать изменения, добавь
`--apply`.

В PowerShell перенос строки — обратная кавычка, а не `\`, и питон
удобнее звать из venv:

```powershell
.\venv\Scripts\python.exe superset\apply_review_fixes.py --url http://superset.example.com:8088 --username admin --phases p0,p1,p2
```

Фазы можно применять по одной (`--phases p0`), но порядок важен:
чарты фазы p1 опираются на колонки, которые появляются в витринах на
фазе p0.

Перед первой записью скрипт выгружает текущее состояние в
`superset_backup_<timestamp>.zip`. Это путь отката: импорт этого ZIP
через UI (Dashboards → Import) или `POST /api/v1/dashboard/import/`
с `overwrite=true` возвращает дашборд в исходный вид.

## Что делает

| Фаза | Правки |
| --- | --- |
| `p0` | Перевод датасетов на витрины (FINAL, словари, `is_mature`), GMV и средний чек только по оплаченным заказам, отсечение незрелого хвоста, распределение времени до первого заказа вместо среднего, перцентили рефанда по сырым длительностям, сортировка «топ-10» и разбивки DQ |
| `p1` | нативная воронка, горизонтальные бары, подписи пирогов, проценты вместо долей, границы оси success rate, скользящее среднее за 7 дней, порядок перцентилей, русские названия вкладок и заголовков |
| `p2` | фильтры периода / города / канала, KPI-строка на обзоре, свежесть загрузки на вкладке качества, палитра и автообновление |

## Что скрипт не делает

- **P0-05.** Скрипт ограничивает конверсию зрелой когортой; чтобы
  метрика вообще начала двигаться, нужны данные, перегенерированные с
  `--never-order-rate` (см. корневой README) — на старых данных она
  останется равной 100%.
- **P1-09.** Переворот оси дней недели задаётся ключом `sort_y_axis`,
  имя которого зависит от версии Superset. Если понедельник остался
  внизу — поправить в UI чарта.
- **P1-10.** Подписи когорт сокращены до `%m-%d`; внутри одного года
  сортируются верно, на стыке лет порядок нужно пересмотреть.

## Выводы на обзоре

Блок «Что видно в данных» — три утверждения с периодом, числом и
указанием, где каждое перепроверить. Текст лежит в `OVERVIEW_FINDINGS`
в `apply_review_fixes.py`.

Причинности в них нет намеренно. Сказать «канал X самый выгодный»
нельзя, не зная расходов на привлечение, а таких данных в модели нет
вовсе: это было бы не выводом, а догадкой, поданной с точностью до
десятой доли процента.

**Числа нужно обновлять после перегенерации данных.** Они относятся к
конкретному периоду, который назван в заголовке блока, и сами собой не
пересчитываются. Актуальные значения берутся так:

```bash
clickhouse-client --database marketplace_marts -q "
SELECT round(sum(has_order)/count()*100, 1) FROM customer_first_order WHERE is_mature = 1"
```

Проверить, что блок не разошёлся с дашбордом, проще всего глазами:
каждый вывод указывает вкладку и график, на которых он виден.

## Язык дашборда и язык кода

Подписи на дашборде намеренно не повторяют терминологию репозитория:
их читает тот, кто смотрит на цифры, а не тот, кто чинит пайплайн.
Соответствие между тем и другим — здесь.

| На дашборде | В коде и в этом репозитории |
|---|---|
| «Каждый платёж считается один раз, по последнему состоянию» | дедупликация `FINAL` по `ReplacingMergeTree`, см. корневой README |
| «Отклонено при загрузке», «отклонённые строки» | карантин: `quarantine_*`, правила в `transform.py` |
| «Найдено ошибок» | срабатывания DQ-правил, таблица `dq_metrics` |
| «Доля отклонённых строк по дням» | `invalid_rows / total_rows` из `dq_metrics` |
| «Сообщение о закрытии заказа было отклонено проверками» | закрывающая строка ушла в карантин, последней валидной осталась открытая |
| «Отставание данных» | `max(hours_since_load)` из витрины `load_freshness` |
| «Старше 34 дней» | горизонт зрелости `maturity_days()` из `growth_config.json` |

Правило простое: в названии чарта, его описании и подписях осей не
должно быть ни имён колонок, ни ключевых слов SQL, ни наших внутренних
слов вроде «карантин» и «сущность». Всё это остаётся в коде и в
README — там оно на своём месте и никому не мешает.

## Настройки самого инстанса

Две вещи скрипт задать не может — они живут в `superset_config.py` на
сервере (в нашем стенде это `/opt/superset/superset_config.py`,
примонтированный в контейнер) и требуют перезапуска Superset.

```python
# Разделители чисел. Без этого «237,5 млн ₽» выглядит как «237.5»,
# а «137 104» — как «137,104».
D3_FORMAT = {
    "decimal": ",",
    "thousands": " ",
    "grouping": [3],
}

# Список языков — не перевод, а именно список.
LANGUAGES = {
    "en": {"flag": "us", "name": "English"},
    "ru": {"flag": "ru", "name": "Russian"},
}
```

`LANGUAGES` выглядит необязательным, но его отсутствие роняет дашборд
целиком, и разбираться в этом дорого. Фронтенд берёт язык из настроек
браузера (`navigator.language`) и ищет его в этом списке. У браузера с
русским языком запись `ru` не находится, `languages["ru"].flag` читается
у `undefined` — и падает инициализация всего приложения. На экране
чёрная страница без единой надписи, в логах сервера чисто, запросы
данных отвечают 200. Видно только в консоли браузера.

Перевода это не даёт: языкового пакета `ru` в сборке Superset нет,
`/superset/language_pack/ru/` отвечает 404, интерфейс остаётся
английским. Запись нужна ровно затем, чтобы фронтенду было что найти.
По той же причине роли Public выдано право `can_language_pack` — иначе
анонимный посетитель получает на этот запрос HTML страницы логина
вместо JSON, разбор падает, и чарты снова перестают рисоваться.

Единицы измерения (`млн ₽`, `₽`) задаются подписью карточки в
`KPI_CHARTS`, а не полем валюты Superset: то принимает код ISO и
печатает «RUB», потому что символ берётся из локали фронтенда. Передать
туда «₽» нельзя — `Intl` не знает такого кода и молча выбрасывает
суффикс вместе с валютой.

## Проверка после применения

1. Воронка: «Создано» должно заметно просесть — незрелые заказы больше
   не считаются. Горизонт зрелости берётся из `growth_config.json` как
   сумма всех дедлайнов (на дефолтах 34 дня), тот же расчёт, что в
   `compute_lookback_days()` генератора: до его истечения заказ ещё
   может отмениться или вернуться.
2. «Способы оплаты и статус»: «Успешно» должно упасть примерно на число
   возвратов — это и есть эффект FINAL.
3. Доли отмен и возвратов: правый край больше не падает в ноль.
