## Скрипт apply_review_fixes.py

### Назначение

Скрипт через REST API Superset:

- переключает датасеты на витрины `marketplace_marts`;
- задаёт `form_data` чартов, раскладку и метаданные дашборда;
- выдаёт роли `Public` доступ к витринам.

SQL витрин в скрипте нет: он находится в `clickhouse_marts.sql` и
применяется загрузчиком (см. «Семантический слой» в корневом README).
Датасет переключается на витрину (`sql=None`, схема `marketplace_marts`)
без пересоздания и переименования, поэтому чарты, ссылающиеся на него по
id, продолжают работать.

Скрипт идемпотентен: повторный запуск приводит инстанс к тому же
состоянию. Без `--apply` он выводит план и ничего не записывает.

Требования:

- Витрины уже созданы в ClickHouse. Их создаёт любой запуск
  `load_to_clickhouse.py`, в том числе для уже загруженного дня, или
  `python clickhouse_ddl.py --marts`.
- В Superset заведена база ClickHouse с доступом к схеме
  `marketplace_marts`. Датасеты создаются в той же базе, что и датасет
  `orders`.
- Superset 4.1 или новее. Неизвестные ключи `form_data` Superset молча
  игнорирует, поэтому несовпадение версии проявляется как несработавшая
  правка, а не как ошибка.

### Установка и запуск

```bash
pip install -r requirements-superset.txt
pip install -e . --no-deps
```

Единственная внешняя зависимость — `requests`.
`requirements-superset.txt` не включает `requirements.txt`: pandas и
pyspark скрипту не нужны. Для воспроизводимой установки есть
`requirements-superset.lock`. Установка проекта (`pip install -e .`) нужна
для импорта `growth.py` из корня репозитория.

```bash
# план
python superset/apply_review_fixes.py --url http://superset.example.com:8088 \
  --username admin --phases p0,p1,p2

# запись
python superset/apply_review_fixes.py --url http://superset.example.com:8088 \
  --username admin --phases p0,p1,p2 --apply
```

В PowerShell перенос строки обозначается обратной кавычкой, поэтому
команду удобнее писать в одну строку:

```powershell
.\venv\Scripts\python.exe superset\apply_review_fixes.py --url http://superset.example.com:8088 --username admin --phases p0,p1,p2
```

| Флаг | Назначение |
|---|---|
| `--phases` | Фазы через запятую: `p0`, `p1`, `p2`. По умолчанию `p0` |
| `--apply` | Записать изменения. Без флага выводится только план |
| `--dashboard` | id дашборда. По умолчанию `1` |
| `--url`, `--username`, `--password` | Подключение. По умолчанию из `SUPERSET_URL`, `SUPERSET_USERNAME`, `SUPERSET_PASSWORD` |
| `--credentials` | Файл с `url`, `username`, `password`. По умолчанию `~/.superset/credentials.json` |
| `--public-role` | Роль, которой выдаётся доступ к витринам. По умолчанию `Public`; пустое значение — роль не изменяется |
| `--narrow-public РОЛЬ` | Оставить роли только права, нужные для просмотра дашборда |
| `--delete-charts` | Удалить чарты по id через запятую |
| `--diagnose` | Вывести, что API отдаёт по датасетам, и завершить работу |

### Фазы

| Фаза | Назначение | Правки |
|---|---|---|
| `p0` | неверные числа | Перевод датасетов на витрины (`FINAL`, словари, `is_mature`); GMV и средний чек только по оплаченным заказам; отсечение незрелых заказов; распределение времени до первого заказа вместо среднего; перцентили возврата денег по исходным длительностям; сортировка «топ-10» и разбивки DQ |
| `p1` | неверное прочтение | Воронка, горизонтальные столбцы, подписи круговых диаграмм, проценты вместо долей, границы оси доли успешных оплат, скользящее среднее за 7 дней, порядок перцентилей, русские названия вкладок и заголовков |
| `p2` | структура | Фильтры периода, города и канала; строка KPI на обзоре; свежесть загрузки на вкладке качества; палитра; автообновление; блок выводов на обзоре |

Фазы применяются и по одной (`--phases p0`), но в порядке p0 → p1 → p2:
чарты фазы p1 используют колонки, которые появляются в витринах на фазе p0.

### Учётные данные

Источники по приоритету: аргумент командной строки, переменная окружения,
файл `--credentials`.

Если пароль не найден, скрипт запрашивает его скрытым вводом. Если ввод
или вывод перенаправлены, скрипт завершается с ошибкой, а не ждёт ввода.
Пароль в аргументе командной строки виден в списке процессов и остаётся в
истории оболочки, поэтому `--password` и `SUPERSET_PASSWORD` предназначены
для окружений без интерактивного ввода.

Для запуска без участия человека, например из ночной задачи DAG, учётные
данные хранятся в файле:

```bash
mkdir -p ~/.superset
cat > ~/.superset/credentials.json <<'JSON'
{"url": "http://localhost:8088", "username": "superset_admin", "password": "..."}
JSON
chmod 600 ~/.superset/credentials.json
```

Файл, доступный кому-либо кроме владельца, скрипт читать отказывается.

### Резервные копии

Перед записью скрипт выгружает дашборд в `superset_backup_<время>.zip` в
текущем каталоге и хранит 10 последних копий (`BACKUPS_KEPT`). Откат —
импорт ZIP через Dashboards → Import или `POST /api/v1/dashboard/import/`
с `overwrite=true`.

### Удаление чартов

```bash
python superset/apply_review_fixes.py --delete-charts 44,45,46          # список к удалению
python superset/apply_review_fixes.py --delete-charts 44,45,46 --apply  # удаление
```

Удаляются только чарты из переданного списка, на которые не ссылается
раскладка дашборда.

### Ограничения

- **Конверсия.** Скрипт ограничивает её зрелыми покупателями, но
  покупателей без заказов не создаёт. На данных, сгенерированных с
  `--never-order-rate 0`, конверсия равна 100 %.
- **Ось дней недели.** Порядок дней задаётся ключом `sort_y_axis`, имя
  которого зависит от версии Superset. Если понедельник оказался внизу,
  порядок исправляется в настройках чарта.

### Проверка после применения

1. Воронка: этап «Создано» уменьшается — незрелые заказы не учитываются.
   Горизонт зрелости — сумма сроков из `growth_config.json`, та же, что в
   `compute_lookback_days()` генератора.
2. «Способы оплаты и статус»: «Успешно» уменьшается примерно на число
   возвратов — результат `FINAL`.
3. Доли отмен и возвратов: правый край графика не падает к нулю.

## Выводы на обзоре

Блок «Что видно в данных» содержит утверждения с периодом, числом и
указанием, где их проверить. Формулировки и SQL находятся в
`overview_findings.py`, числа подставляются из ClickHouse при каждом
применении правок, в том числе ночной задачей `refresh_dashboard`. Числа
относятся к периоду данных, поэтому вписывать их вручную нельзя: после
очередной загрузки они перестали бы соответствовать данным.

Вывести блок, не меняя дашборд:

```bash
python overview_findings.py
```

Если ClickHouse недоступен, текст на дашборде не меняется, а скрипт
выводит предупреждение.

Причинно-следственных утверждений в выводах нет: данных о расходах на
привлечение в модели нет, и вывод «канал X выгоднее» был бы догадкой.
Запрет проверяет `tests/test_overview_findings.py`: тест падает на словах
«выгоднее», «рентабельнее», «из-за» и подобных.

## Подписи дашборда

Подписи на дашборде рассчитаны на читателя цифр, а не на разработчика
пайплайна, поэтому терминология отличается от терминологии кода.

| На дашборде | В коде |
|---|---|
| «Каждый платёж считается один раз, по последнему состоянию» | дедупликация `FINAL` по `ReplacingMergeTree` |
| «Отклонено при загрузке», «отклонённые строки» | карантин: `quarantine_*`, правила в `transform.py` |
| «Найдено ошибок» | срабатывания DQ-правил, таблица `dq_metrics` |
| «Доля отклонённых строк по дням» | `invalid_rows / total_rows` из `dq_metrics` |
| «Сообщение о закрытии заказа было отклонено проверками» | закрывающая строка заказа ушла в карантин, в хранилище осталась открытая версия |
| «Отставание данных» | `max(hours_since_load)` из витрины `load_freshness` |
| «Старше 34 дней» | горизонт зрелости `maturity_days()` из `growth_config.json` |

Правило: в названиях, описаниях и подписях осей чартов нет имён колонок,
ключевых слов SQL и внутренних терминов вроде «карантин» и «сущность».

## Настройки инстанса

Следующие настройки скрипт задать не может. Они находятся в
`superset_config.py` (на стенде — `/opt/superset/superset_config.py`,
копия в `deploy/`) и применяются после перезапуска Superset.

```python
# Разделители чисел: «237,5 млн ₽» вместо «237.5», «137 104» вместо «137,104».
D3_FORMAT = {
    "decimal": ",",
    "thousands": " ",
    "grouping": [3],
}

# Список языков интерфейса.
LANGUAGES = {
    "en": {"flag": "us", "name": "English"},
    "ru": {"flag": "ru", "name": "Russian"},
}
```

**`LANGUAGES` обязателен.** Фронтенд берёт язык из `navigator.language` и
ищет его в этом списке. Если браузер русскоязычный, а записи `ru` нет,
обращение `languages["ru"].flag` падает, и приложение не
инициализируется: страница пустая, в логах сервера ошибок нет, запросы
данных отвечают 200. Ошибка видна только в консоли браузера.

Перевода интерфейса запись не даёт: языкового пакета `ru` в сборке нет,
`/superset/language_pack/ru/` отвечает 404. По той же причине у роли
`Public` есть право `can_language_pack`: без него анонимный посетитель
получает вместо JSON страницу входа, и чарты не отрисовываются.

**Единицы измерения** (`млн ₽`, `₽`) задаются подписью карточки в
`KPI_CHARTS`, а не полем валюты Superset. Поле валюты принимает код ISO и
выводит «RUB»; символ «₽» `Intl` не распознаёт и отбрасывает вместе с
валютой.

## Стенд

### Конфигурация

Конфигурация стенда хранится в `deploy/`:

| Файл | Расположение на сервере |
|---|---|
| `nginx-marketplace-analytics.conf` | `/etc/nginx/sites-available/marketplace-analytics` |
| `docker-compose.yml` | `/opt/superset/docker-compose.yml` |
| `Dockerfile` | `/opt/superset/Dockerfile` |
| `superset_config.py` | `/opt/superset/superset_config.py` |

Расположение также указано в первой строке каждого файла. Секретов в файлах
нет.

Файлы находятся вне каталога проекта на сервере, и выкладка через git их не
обновляет: изменения переносятся вручную в обе стороны. Расхождение
проверяется сравнением `md5sum` локальной копии и файла на сервере.

### Выкладка кода

```bash
git push server master
```

`server` — git-remote, указывающий по SSH на каталог проекта на сервере.
Push в рабочую копию разрешён настройкой
`receive.denyCurrentBranch = updateInstead`: она обновляет историю и файлы,
но только если в рабочем каталоге на сервере нет незакоммиченных изменений.
Отказ push означает, что файлы на сервере изменены вручную.

Копировать файлы на сервер через `scp` нельзя: содержимое станет новым, а
git на сервере продолжит считать актуальной прежнюю версию, и рабочий
каталог станет «грязным», что заблокирует следующий push.

DAG подключён к Airflow симлинком `~/airflow/dags/daily_marketplace_pipeline.py`
на файл в каталоге проекта и отдельной выкладки не требует.

### Схема доступа

```
браузер → https://marketplace-analytics.andrewsalmin.com  (nginx, Let's Encrypt)
                        ↓ proxy_pass
              http://127.0.0.1:8088                       (gunicorn в контейнере)
```

`andrewsalmin.com/marketplace-analytics` отвечает редиректом 301 на
поддомен. Подпуть не используется: в этой сборке Superset нет
`SUPERSET_APP_ROOT` и `APPLICATION_ROOT`, и ссылки на статику и API
строятся от корня. На подпути это потребовало бы переписывания URL в nginx.

Обязательные настройки:

- **`--bind 127.0.0.1:8088`** в `docker-compose.yml`. Контейнеры работают
  с `network_mode: host`, и привязка к `0.0.0.0` открыла бы Superset
  наружу по HTTP в обход nginx, с передачей пароля администратора открытым
  текстом. Postgres и Redis также привязаны к `127.0.0.1`.
- **`ENABLE_PROXY_FIX = True`** в `superset_config.py`. Без него Superset
  не доверяет заголовку `X-Forwarded-Proto` от nginx и считает соединение
  HTTP.

Проверка извне, не с сервера:

```bash
curl --max-time 10 http://89.169.173.91:8088/    # соединение не устанавливается
curl -sL -o /dev/null -w '%{http_code}\n' https://andrewsalmin.com/marketplace-analytics    # 200
```

### Скриншоты для README

Картинки корневого README в репозитории не хранятся: они ссылаются на
`https://marketplace-analytics.andrewsalmin.com/shots/`, где nginx отдаёт
каталог `/var/www/marketplace-shots` (`location /shots/`).

Снимки делает `docs/refresh_screenshots.sh`: headless Chrome открывает
публичный адрес дашборда и сохраняет `overview.png` и `dq.png`. Скрипт
запускает задача `refresh_screenshots` в конце ежедневного DAG, после
обновления дашборда. Ручной запуск — на сервере, из каталога проекта:

```bash
docs/refresh_screenshots.sh
```

Файл меньше 50 КБ считается неотрисованной страницей: скрипт делает до
трёх попыток и при неудаче оставляет прежний снимок. Новый снимок заменяет
старый переименованием, поэтому недописанный файл не отдаётся.

Снимки не коммитятся: ежедневный коммит двух PNG добавил бы за год около
сотни мегабайт и сотни коммитов без изменений кода. Картинки в README
доступны, пока работает стенд.

### Секреты

Пароль Postgres и `SECRET_KEY` передаются контейнерам файлами Docker
secrets, а не переменными окружения:

```yaml
secrets:
  postgres_password:
    file: ./secrets/postgres_password
  superset_secret_key:
    file: ./secrets/superset_secret_key
```

Переменная окружения видна в `docker inspect`, в `/proc/<pid>/environ` и
наследуется дочерними процессами. Файл секрета монтируется только в
контейнеры, где он объявлен.

`superset_config.py` читает секреты функцией `_secret()`; если файла нет,
значение берётся из прежней переменной окружения.

Каталог `/opt/superset/secrets` в репозиторий не входит. Права: каталог
`700`, файлы `644`. Режим `600` для файлов не подходит: `postgres_password`
читают два контейнера под разными пользователями — `postgres` (uid 999) и
`superset` (uid 1000), — а владелец у файла один. При режиме `600` Superset
не стартует, в логе только «Worker failed to boot». Посторонний пользователь
хоста в каталог с режимом `700` не попадёт.

Проверка, что секретов в окружении контейнера нет:

```bash
sudo docker inspect superset --format '{{range .Config.Env}}{{println .}}{{end}}' \
  | grep -E 'PASSWORD=|SECRET_KEY=|SQLALCHEMY_DATABASE_URI='    # вывод пустой
```

Файл `.env` со значениями секретов не используется.

### Права анонимного посетителя

Дашборд открыт без входа, и права роли `Public` определяют, что доступно
анониму. Права сужаются отдельной командой:

```bash
python superset/apply_review_fixes.py --narrow-public Public          # план
python superset/apply_review_fixes.py --narrow-public Public --apply  # запись
```

Команда не входит в обычный прогон: снятие прав может сделать дашборд
пустым, и выполняется оно только явно. Перед записью состав роли
сохраняется в `superset_role_Public_<время>.json`, после записи
сверяется с ожидаемым.

Итоговый набор строится с нуля:

- доступ к датасетам, которые используют чарты дашборда (список берётся из
  самих чартов);
- функциональные права из `PUBLIC_REQUIRED_PERMISSIONS`:

| Право | Для чего |
|---|---|
| `can_dashboard on Superset` | страница дашборда |
| `can_read on Dashboard` | список чартов и раскладка, `GET /api/v1/dashboard/{id}` |
| `can_read on Chart` | данные чартов, `POST /api/v1/chart/data` |
| `can_time_range on Api` | фильтр периода, `/api/v1/time_range/` |
| `can_language_pack on Superset` | словарь переводов; без него не отрисовываются чарты |

Анониму не выдаются:

| Право | Причина |
|---|---|
| `schema_access on [...].[marketplace_analytics]` | доступ ко всей исходной схеме, включая карантин, `dq_metrics` и `_load_commits` |
| `can_read on Dataset` | `GET /api/v1/dataset/` отдаёт описания датасетов вместе с SQL виртуальных |
| `can_explore_json on Superset` | устаревший эндпоинт данных; дашборд использует `/api/v1/chart/data` |
| `can_get on Datasource`, `can_external_metadata on Datasource` | служебные права конструктора чартов |

После сужения прав дашборд проверяется визуально: при нехватке прав
страница отвечает 200, но чарты пустые. Снимок без входа:

```bash
google-chrome --headless --disable-gpu --no-sandbox \
  --window-size=1600,1000 --virtual-time-budget=90000 \
  --screenshot=/tmp/check.png 'http://localhost:8088/superset/dashboard/1/'
```

Закрытые эндпоинты должны отвечать 401:

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8088/api/v1/dataset/
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8088/api/v1/database/
```
